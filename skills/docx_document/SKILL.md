# Word Document Generator

You create `.docx` files using **python-docx only**. It is installed in
PELDRUN. Do **not** shell out to LibreOffice, Word COM automation,
`pandoc`, `docx2pdf`, or `python-docx-template` — they are not installed
and require external binaries or elevated permissions.

## Why python-docx

`python-docx` writes OOXML directly and stores text as Unicode, so
Arabic, Hebrew, CJK, and Cyrillic survive round-trip without font
registration. Word applies the document's font and shapes text at
display time. The only manual step is per-paragraph RTL alignment and
the run-level RTL flag (see "RTL rules" below).

No "tofu" risk here: Word — not the generator — handles font fallback.

## Before you write code

Ask the user (or infer from context):

1. **Output path** — default `<workspace>/<name>.docx`. Never hardcode
   `C:\...` or `/tmp/...`.
2. **Language** — one primary language per document. Mixed documents
   (English title, Arabic body) are supported; set alignment per
   paragraph, not globally.
3. **Structure** — title, sections, tables, images, headers/footers.
4. **Data source** — parse provided CSV/text/numbers first.
   **Never invent data.**
5. **RTL** — Arabic, Hebrew, Persian, or Urdu content needs per-paragraph
   `alignment = RIGHT` and `run.font.rtl = True` (see "RTL rules").

## Canonical script

Create `generate_docx.py` in the workspace. This is a complete, runnable
script — do not abbreviate.

```python
from pathlib import Path
from docx import Document
from docx.shared import Pt, Cm, RGBColor
from docx.enum.text import WD_ALIGN_PARAGRAPH
from docx.enum.table import WD_TABLE_ALIGNMENT

output_path = Path("report.docx")
doc = Document()

# --- Title ---
title = doc.add_heading("Monthly Report", level=0)

# --- Intro paragraph ---
p = doc.add_paragraph("Generated by PELDRUN.")
p.alignment = WD_ALIGN_PARAGRAPH.LEFT

# --- Section heading ---
doc.add_heading("Highlights", level=1)

# --- Bullet list ---
for item in ["Revenue up 20%", "Churn down 5%", "NPS at 45"]:
    doc.add_paragraph(item, style="List Bullet")

# --- Table ---
table = doc.add_table(rows=1, cols=3)
table.style = "Light Grid Accent 1"
table.alignment = WD_TABLE_ALIGNMENT.CENTER

header = table.rows[0].cells
for i, label in enumerate(["Item", "Qty", "Price"]):
    header[i].text = label
    for run in header[i].paragraphs[0].runs:
        run.bold = True

rows_data = [("Widget", "10", "$5.00"), ("Gadget", "3", "$12.50")]
for item, qty, price in rows_data:
    row = table.add_row().cells
    row[0].text = item
    row[1].text = qty
    row[2].text = price

# --- Image (verify first) ---
logo = Path("logo.png")
if logo.exists():
    doc.add_picture(str(logo), width=Cm(4))

# --- Page break + appendix ---
doc.add_page_break()
doc.add_heading("Appendix", level=1)
doc.add_paragraph("End of document.")

doc.save(str(output_path))
print(f"OK: {output_path} ({output_path.stat().st_size} bytes)")
```

Run it with `python_execute` or via `bash`: `python generate_docx.py`.

## RTL rules (critical)

python-docx does **not** set RTL automatically. For every paragraph
whose primary text is Arabic, Hebrew, Persian, or Urdu, you must do
**both** of the following:

```python
p = doc.add_paragraph(arabic_text)
p.alignment = WD_ALIGN_PARAGRAPH.RIGHT

for run in p.runs:
    run.font.rtl = True
```

- `alignment = RIGHT` aligns the paragraph to the right margin.
- `run.font.rtl = True` tells Word to treat the run as RTL text so that
  punctuation, numbers, and mixed Latin words appear in the correct
  position.

**If you set only `alignment`**, Arabic text displays right-aligned but
mixed-script lines render in the wrong order (e.g. `(20%)` appears on
the wrong side of an Arabic phrase).

**If you set only `run.font.rtl`**, the paragraph remains left-aligned
and Word displays Arabic content starting from the wrong margin.

**Never** reverse characters, insert Unicode bidi controls, or manually
reorder punctuation. Word handles bidi layout when `rtl=True`.

For a mixed document (English headings, Arabic body), apply this per
paragraph — not globally:

```python
def add_rtl_paragraph(doc, text):
    p = doc.add_paragraph(text)
    p.alignment = WD_ALIGN_PARAGRAPH.RIGHT
    for run in p.runs:
        run.font.rtl = True
    return p

add_rtl_paragraph(doc, arabic_body_text)
```

True paragraph-level RTL direction (the `w:bidi` element) is rarely
needed; if the user reports that numbers still appear reversed inside an
Arabic sentence, see `references/examples.md` for the low-level XML
workaround.

## Tables

```python
table = doc.add_table(rows=1, cols=3)
table.style = "Light Grid Accent 1"       # or "Table Grid", "Light List"
table.alignment = WD_TABLE_ALIGNMENT.CENTER
```

- Add rows with `table.add_row().cells`.
- Bold headers by iterating `cell.paragraphs[0].runs` and setting
  `run.bold = True`.
- For RTL tables, set `table.alignment = RIGHT` and RTL each cell's
  runs like a paragraph.

## Images

```python
from docx.shared import Cm

if not Path("logo.png").exists():
    raise FileNotFoundError("logo.png not found in workspace")

doc.add_picture("logo.png", width=Cm(4))
```

- Always pass `width` (or `height`). Without it, python-docx uses the
  image's native size, which is often huge.
- Supported formats: PNG, JPEG, GIF (first frame), BMP, TIFF.
- SVG is **not** supported by python-docx. Convert to PNG first.
- `doc.add_picture` appends a centered paragraph containing the image.
  For inline-left, add the picture to an existing paragraph via
  `run.add_picture("logo.png", width=Cm(4))`.

## Page setup, headers, footers

section = doc.sections[0]
section.page_width, section.page_height = Cm(21.0), Cm(29.7)  # A4
section.top_margin = section.bottom_margin = Cm(2.0)
section.left_margin = section.right_margin = Cm(2.0)
section.header.paragraphs[0].text = "Company Confidential"
section.footer.paragraphs[0].text = "Page footer text"
```

Page numbering requires a field code (not plain text). Skip page
numbers unless the user explicitly asked — see
`references/examples.md` for the field-code snippet.

## Verification (mandatory)

Always verify **before** reporting success.

```python
from pathlib import Path
from docx import Document

p = Path(output_path)
assert p.exists(), "DOCX file was not created"
assert p.stat().st_size > 1000, f"DOCX too small ({p.stat().st_size} bytes)"

# python-docx can open the file it just wrote — this catches
# malformed OOXML (e.g. from a crashed save).
verify = Document(str(p))
print(f"Paragraphs: {len(verify.paragraphs)}")
print(f"Tables:     {len(verify.tables)}")
assert len(verify.paragraphs) >= 1, "Document has no paragraphs"
```

If verification fails, do **not** report success. Report the exact
traceback.

## Hard rules

1. **Use python-docx only.** Never LibreOffice, Word COM, `pandoc`,
   `docx2pdf`, or `python-docx-template`.
2. **Never install packages** at runtime. If python-docx is missing,
   report it and stop.
3. **Never write outside the workspace.** All output paths must be
   relative to `<workspace>`.
4. **Always run verification** before reporting success.
5. **Arabic/Hebrew text: set `alignment=RIGHT` AND `run.font.rtl=True`
   on every run.** Setting only one produces reversed punctuation or
   wrong-margin text.
6. **Never reverse characters or insert bidi controls manually.**
7. **Always pass `width` to `add_picture`.** Without it, images overflow
   the page.
8. **Never claim success without a file on disk that opened
   successfully.**
9. **Never invent data.** If the user did not provide values, ask.
10. **Never hardcode absolute paths** like `C:\...` or `/tmp/...`.
